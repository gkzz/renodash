# ドキュメントの書き方

英語と日本語のドキュメントを textlint で校正します。短い文を使い、関連する項目は箇条書きで整理します。

## 日本語を書くときの目安

- 一文で伝える主な内容はひとつにします。長い文は分割し、120文字以内に収めます。
- 機能や要件の列挙には箇条書きを使います。順序がある手順には番号を付けます。
- 段落ごとに話題を絞り、最初の文で要点を伝えます。
- コマンドの実行場所と前提条件を説明し、コマンドはコードブロックに書きます。
- コマンド名、JSON のキー、版、日時、URL は正確に記載します。
- 調査で確認した事実と推測を区別します。未確認の内容は未確認と書きます。
- 同じルールや手順は一か所にまとめ、他の場所からはリンクで参照します。重複した記載を極力減らし、更新時の二重管理を避けます。

仕様・設計・開発手順のような長く使える知識をドキュメントに残します。
進捗、仕様やテストの不足、今後の作業は GitHub Issues で管理します。
既存の調査記録を推敲するときは、内容の確実さや当時の状況を保ちます。
保存した Dashboard 本文や JSON の値は、文章の校正に合わせて書き換えません。

仕様書の作成や構成の整理には、[仕様書テンプレート](templates/spec-template.md)を使います。
適用方針は[英語ガイドの仕様書構成](writing.md#behavior-specification-structure)を参照してください。

## 校正の実行

ツールの準備、校正コマンド、自動修正の手順は、[英語ガイドの実行手順](writing.md#run-the-checks)を参照してください。

## 対象と設定

対象ファイル、命名規則、設定ファイル、検査ルールは、[英語ガイドの対象とルール](writing.md#scope-and-rules)を参照してください。
README と調査メモでは文体が異なるため、ですます調とである調の統一は手作業で確認します。

textlint は文章の校正を補助する道具です。技術的な正しさや調査結果は、根拠と照らし合わせて確認してください。
英語の執筆ルールは [Writing documentation](writing.md) を参照してください。
